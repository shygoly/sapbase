# 原子输出管控（闸 3）判据

> 版本：v1
> 日期：2026-09-25
> 定位：**闸 3 的唯一判据文本**。实现（`backend/src/atomic-runtime/output-gate.ts`）只做本文件里的判定；
> 想要加判据，先改本文件（元语不变量 10：未冻结的协议不做实现）。
> 相关：`docs/META_LANGUAGE.md` §3.3（准入闸表）、`schemas/atomic-contract.schema.json`（声明的真源）。

---

## 0. 前提：原子能做什么、不能做什么

ABI v1 下原子**没有任何读写能力**：只有 `in` / `out` 两块缓冲区与一个 `run` 导出。
所以它不能把库里的数据偷出去。但它仍然可以：

1. 把**编在代码里的常量**当成结果交出来（藏在某列的高位上）
2. 让输出**取决于行数或行序**，给自己开一条隐蔽信道
3. 写出**超出声明值域**的值，把调用方下游弄脏

闸 3 判的就是这三件事。它**不判**"算得对不对"——那是契约 `outputSchema` 与调用方的责任。

---

## 1. 判据

四条**判决**（命中即拒绝返回结果）+ 一条**信号**（只写审计）+ 一条**条件判决**（声明后才判）：

| # | 判据 | 类型 | 判什么 | 声明来源 |
| --- | --- | --- | --- | --- |
| O1 | 结构封闭 | 判决 | 输出只由声明的列与汇总位构成：不缺列、不多列、列序一致 | `outputSchema.columns` / `.total` |
| O2 | 值域 | 判决 | 每个值在声明的 `minimum` / `maximum` 内；未声明时按 i32 边界兜底 | 列的 `minimum` / `maximum` |
| O3 | 大小上限 | 判决 | 输出总字节 ≤ `maxOutputBytes` | `outputSchema.maxOutputBytes` |
| O4 | 批量-单条一致 | 判决 | 同一组输入，批量一次算与逐条各算再拼，结果逐值一致（输入 < 2 行时无从判别，记「未判」） | 无需声明 |
| O5 | 置换不变 | 条件判决 | 打乱输入行序后输出行**随之重排**、汇总位不变 | `output.commutative: true` |
| S1 | 常量位模式 | **信号** | 某输出列**整列同值** | 无需声明 |

### 1.1 为什么 S1 是信号而不是判决

合法的原子完全可能输出常量：空输入返回全 0 汇总、把税率取整到固定档位、边界值裁剪。
把这类原子拦下来，会让人**关掉整个闸**——那比没有闸更糟。
因此 S1 只写审计，交给人看；判决必须是能说清"违反了哪条声明"的那几条。

**被否掉的 S1 变体：恒定高位。** 初稿还打算报"整列共享同一段高位"（常量藏高位是
`leaky-output-bits` 夹具的手法）。自己写完就发现不能要：**任何两个小整数的高位都相同**，
于是这条信号几乎次次触发 —— 一条每回都亮的信号等于没有信号，还会训练人忽略审计。
真正能判"高位被塞了东西"的是 **O2**，前提是契约**声明了值域**：那是作者对
"值应该长什么样"的显式承诺，不是平台的猜测。所以 v1 的立场是：
**要拦高位夹带，就把值域声明写清楚**，而不是让平台去猜。

### 1.2 O5 为什么默认不判

"打乱行序后输出应当重排"只对**声明可交换**的原子成立。多数原子不是（例如按行累积的滚动余额）。
判不了就**如实记"未判"**，而不是默认通过——审计里写的是"O5 未判"，不是"O5 通过"。

## 2. 明确不判什么

写在这里，是为了以后有人想加时先读到这段：

- **不做统计显著性检验、不做抽样、不做模糊测试**。四五个样本撑不起统计结论，只会得到随机的红绿。
- **不判业务正确性**（"这个库存数合理吗"）。那是契约与调用方的事。
- **不判性能**。资源预算由 fuel / epoch 管（见 `docs/META_LANGUAGE.md` §3.2）。
- **不判 `commutative` 未声明的原子的置换不变性**（见 1.2）。
- **不报"恒定高位"信号**（见 1.1）——v1 只报"整列同值"。
- **不判"信息论意义上的信道容量"**。v1 只做上面这些确定性判据；上界问题留给后续变更。

## 3. 档位

档位进契约（`outputAudit`），不是全局配置——因为代价因原子而异：

| 档位 | 判据 | 代价 |
| --- | --- | --- |
| `off` | 只判 O1 / O2 / O3（**不额外执行**） | 0 |
| `standard`（默认） | `off` + O4 + S1 信号 | 追加 `min(行数, 64)` 次逐行重放 |
| `strict` | `standard` + O5 置换重放 | 追加 1 次置换重放（另加逐行重放） |

追加的执行**计入同一 `cpuBudget`**，不放宽预算。审计里记录实际跑了几个内核回合，
这样"闸 3 让这次调用贵了多少"是可查的，不靠猜。

**重放上限（`GATE_MAX_REPLAY_ROWS = 64`）**：逐行重放是 n 次执行，成本随行数线性增长。
超过上限时只判**前 64 行**，报告里记 `rowsJudged` —— 这是确定性的截断，**不是抽样**：
抽样得到的是随机结论，截断得到的是"少判了一段，且写在脸上"。

## 4. 结果形态

闸 3 的输出是一份**判定报告**，与结果一起进审计（命中判决时结果不返回）：

```json
{
  "profile": "standard",
  "verdicts": {
    "O1": { "judged": true, "passed": true },
    "O2": { "judged": true, "passed": false, "detail": "available=1589641223 超出契约值域 [0, 1000000]" },
    "O3": { "judged": true, "passed": true, "bytes": 48 },
    "O4": { "judged": true, "passed": true, "rowsJudged": 2 },
    "O5": { "judged": false, "reason": "契约未声明 commutative" }
  },
  "signals": [{ "code": "constant-column", "column": "available", "note": "整列同值（5），与输入的关系值得看一眼" }],
  "rounds": 3
}
```

两条硬要求：

1. **`judged: false` 必须带 `reason`**，不允许出现"没判但看起来像通过"的空白。
   （注意 `passed` 在未判时是 `false` —— 它表示"没有通过"，而不是"判出来不通过"；
   调用方判"是否被拦"要看 `judged && !passed`。）
2. 命中判决时**两个码都要有**：运行时错误面（如 `OUTPUT_OUT_OF_RANGE`，用于 HTTP 映射）与
   协议码 `protocolCode = atomic.output.<判据>`（如 `atomic.output.O2`）。
   调用方据此可以精确判断"是闸 3 拦的、拦在哪一条"，而不是收到一句"执行失败"。

## 5. 兼容性

- `outputAudit` 与 `commutative` 都是**可选**声明；未声明即按默认档位与"未判"处理。
- 本判据**不改 ABI**：闸 3 在宿主侧完成，模块不需要知道它的存在。
- 新增判据 = 新的协议版本 + 新一轮回归；不允许在实现里悄悄加一条没有写进本文件的检查。
