# 教育智能体需求 → 平台能力 → OpenSpec 对照矩阵

> 用途：内部评估材料，用于判断“哪些是平台通用能力、哪些是教育垂直能力、哪些已有/待实现”。
> 基准：`docs/教育智能体定制开发详细需求说明（合作评估版）.md`、当前代码、`openspec list`（2026-11-09）。
> 本文件不替代需求文档，也不对外披露。

## 图例

| 标记 | 含义 |
|---|---|
| **P0** | 教育项目验收前必须具备的新平台能力（本次要立的 change） |
| **P1** | 重要但可在 P0 后交付的新平台能力 |
| **复用** | 已有实现或已有/待实现 OpenSpec change 覆盖，不重复计划 |
| **垂直** | 教育业务能力，做成 Blueprint / 业务应用 / 可复用模块，不进平台核心 |
| **外部** | 依赖客户环境、外部系统或第三方 provider |
| **UI** | 前端/客户端实现，通常随垂直应用交付 |

## 总览

| 分类 | 数量（约） | 说明 |
|---|---|---|
| 复用已有/待实现平台能力 | 30+ | 多租户、RLS、数据范围、RBAC、UI Runtime、Agent Runtime、工具契约、知识/评测、发布、插件、配额 |
| 新增平台 P0 能力 | 9 类 | 身份、审批、资产、异步任务、导入导出、通知、审计、集成、指标看板 |
| 新增平台 P1 能力 | 4—5 类 | AI 内容治理、文档智能、内容树/生命周期、离线包、搜索 |
| 教育垂直能力 | 40+ | 课程/知识点、班级/学生、教学任务、学习记录、测评、推荐、徽章、评价、工作台 |
| 外部依赖 | 6 类 | 统一身份、教务数据源、模型/智能体、内容安全、视频/媒体、现有系统联调 |

## 建议路线图（90 天）

| 阶段 | 时间 | 内容 |
|---|---|---|
| Wave 0 | 1—2 周 | 批准数据范围 change；搭教育 Blueprint 骨架；锁定客户 SSO 协议、教务数据源、媒体 provider |
| Wave 1 | 2—6 周 | 身份/SSO、审批/工作项、资产管道、异步任务、导入导出、通知中心、审计合规 |
| Wave 2 | 6—10 周 | 外部连接器、指标看板、AI 内容治理、文档智能 |
| Wave 3 | 10—12 周 | 教育垂直模块、离线/搜索、性能与验收 |

**裁剪建议**：通用 BI 设计器、向量检索、复杂推荐、完整离线 SDK 可后置；先交付 7 个核心指标、规则推荐、MP4 离线包。

## 关键风险

1. SSO/身份源依赖客户环境，必须最早启动。
2. 媒体/视频生成不要平台自研，用 provider 插件；平台只做 job + 资产 + 水印钩子。
3. 指标口径必须先冻结，否则看板反复返工。
4. AI 生成内容标识是合规项，覆盖下载/离线/分享/导出/转码。
5. 数据范围启用前做空绑定预检；班级/课程节点必须先配置。
6. 不要把 school/class 等教育词写进平台核心；用 scope dimension/binding。
