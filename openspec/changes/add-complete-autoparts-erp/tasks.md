# Implementation Tasks

## 完整性判据（唯一一条，跨全部阶段）

```text
客户说：「08 款卡罗拉前刹车片，200 套，走宁波华兴的账期」
  ① 车型适配 → ② ATP（含替代件合并）→ ③ 报价（客户等级价）→ ④ 多行订单 + 单号
  → ⑤ 信用检查 → ⑥ 审批（含金额合计）→ ⑦ 确认订单（状态迁移 + 批次占用）
  → ⑧ 发货 / 开票（记账分录）→ ⑨ 反查「这批货卖给了谁」
```

每一步都必须由**平台判定**（不是由模板作者手写脚本），且失败一律拒、不部分执行。
**这条闭环跑不通，就不能宣告"完整"。**

## 里程碑与验收门

| 阶段 | 范围 | 验收门（命令 + 期望） |
| --- | --- | --- |
| **P0** 表达力 | `blueprint-semantic` 扩展 | 模板能声明主从/唯一/金额精度/枚举/计算字段；负例（未知类型、非法精度、循环计算字段）被拒 |
| **P1** 单据运行时 | `document-runtime` | 头+行**原子写入**；单号并发不重；状态迁移被执行；查询可分页排序 |
| **P2** 判定执行 | `semantic-runtime` 扩展 | 审批求值含金额合计；记账分录生成且借贷可判；唯一约束**落到 DB 索引** |
| **P3** 汽配能力 | `autoparts-capabilities` | ATP/价格/信用/换算/替代件原子过闸 0/1/2；适配匹配走宿主查询 |
| **P4** 追溯治理 | 同上扩展 | 批次→客户反查可用；导入非法行逐条报错；三个常用视图免写 SQL |
| **P5** 交付演进 | `blueprint-delivery` 扩展 | 模板 1.0.0→1.1.0 升级后旧数据仍可读；升级后**重新签名**；货币不可混加 |

### 执行约定

1. 每完成一项：勾选 + 附证据（命令 + 结果），不写"应该可以"。
2. **协议先行**：每个阶段的 Schema/协议文本先冻结，再写实现（元语不变量 10）。
3. **不放松既有闸**：新增原子必须过闸 0/1/2/5；新增入口必须过权限与审计。
4. fail-closed：任一判定不过即拒且不部分执行（尤其是"头 + 行"的写入）。
5. 不新造第二份判定：权限复用 `missingPermissions`，审计复用 `audit_logs`，
   签名复用 Ed25519 那条链，状态机复用 `canPromote` 的思路。
6. 每阶段结束跑全量回归（单元 + e2e + wasm-modules + tsc + `verify-from-zero`）。
7. **允许阶段内拆子变更**：某个阶段过大时（P3 最可能），可在该阶段内另立变更；
   但完整性判据与本节第 2–5 条不变。

## Phase P0: 表达力（协议层）

- [ ] **主从结构**：`semantic.json` 支持 `children`（头声明行实体）与 `parent`（行声明归属）；
      编译期判据：parent 字段必须指向声明的头实体；头声明的 children 必须存在
- [ ] **唯一性**：字段级 `unique: true`；编译期判据 + **迁移生成唯一索引**（含既有数据冲突清单）
- [ ] **金额与精度**：`decimal(p,s)` + `rounding`（`half-up` / `half-even`）；禁止用 `number` 表达金额
- [ ] **枚举字段**：`type: "enum"` + `values: [...]`；空集合、重复值被拒
- [ ] **计算字段**：`computed: { expr, dependsOn }`；**循环依赖被拒**；引用不存在的字段被拒
- [ ] **关系基数**：`relations[].cardinality`（`one` / `many`）；多对多需要显式中间实体
- [ ] **单位与换算**：`uom: { base, packs: [{ name, factor }] }`；factor 必须为正整数或有理数
- [ ] 负例覆盖：未知类型 / 非法精度 / 循环计算字段 / children 与 parent 不一致 / 唯一性与既有冲突
- [ ] IR 摘要覆盖新声明（改一处 → `irDigest` 变）

## Phase P1: 单据运行时

- [ ] **事务**：`POST /records/:entity` 支持头 + 行一次提交（要么全落要么全不落）
- [ ] **单据编号**：模板声明编号规则（前缀 + 日期 + 流水）；**并发下不重号**（DB 序列或唯一索引重试）
- [ ] **状态迁移执行**：`POST /records/:entity/:id/transition`（目标状态）；非法迁移拒
- [ ] **查询**：分页 / 排序 / 按字段与状态过滤
- [ ] **关系完整性**：删除被引用的实例 → 拒（或声明为 `cascade` 时按策略处理）
- [ ] jest：头行事务（行写入失败 → 头也不在）；并发建单不重号；非法迁移拒；删除被引用拒

## Phase P2: 判定执行

- [ ] **表达式求值器**：受限语法（比较 + 布尔 + **算术**）的确定性求值；
      只在判定点求值，不进模板语言
- [ ] **审批执行**：`approval.when` 求值 → 需要审批时单据进入待审状态并记录审批链；
      含**金额合计**（依赖 P0 的计算字段）
- [ ] **记账分录**：`accounting` 在事件触发时生成分录；借贷平衡**在运行时也判**（不只编译期）
- [ ] **约束落库**：唯一索引 + 非空约束；冲突时返回可定位的错误
- [ ] jest：金额合计审批；分录借贷平衡；唯一约束由 DB 兜住（应用层绕过也拦）

## Phase P3: 汽配能力（原子）

- [ ] `autoparts-atp`：可用量（含存量/预留/已承诺/在途），**替代件合并**
- [ ] `autoparts-price`：客户等级价 / 阶梯价 / 最近成交价（优先级显式）
- [ ] `autoparts-credit`：额度 − 应收 − 在途 → 结论 + 依据
- [ ] `autoparts-uom-convert`：单位换算（不产生浮点误差）
- [ ] `autoparts-supersession`：替代链解析（旧件 → 新件，含方向与合并规则）
- [ ] 每个原子：过闸 0/1/2 + 进 `build/manifest.json` + 契约登记 + 权限点
- [ ] 车辆适配匹配：宿主查询（车型/年款/位置 → 零件候选），**不做成原子**（理由见 design §3.4）

## Phase P4: 追溯与治理

- [ ] **批次追溯**：`GET /traceability/batch/:code` → 相关单据与客户（**反向查询**，不是"有日志"）
- [ ] **主数据导入**：CSV/JSON 导入零件/客户/供应商；**非法行逐条报错**（不是整批失败，也不是静默丢弃）
- [ ] **查询视图**：库存 / 应收 / 在途 三个视图（模板可声明，或平台内置）
- [ ] e2e：一张含批次发货的单 → 用批次号反查到客户

## Phase P5: 交付演进

- [ ] **模板升级**：`templates/auto-parts/` 1.0.0 → 1.1.0；新增字段必须有默认值或迁移路径；
      旧数据装载后仍可读
- [ ] **升级后重新签名**：模板变更即 `irDigest` 变 → 签名必须重做（授权绑定不能绕过）
- [ ] **货币**：金额带货币；**不同货币不得相加**（编译期 + 运行时都判）
- [ ] **权限细化**：字段级（成本价）、单据级（只看自己的单）、数据范围
- [ ] 文档：`docs/META_LANGUAGE.md` 补"主从结构 / 唯一性 / 金额精度"三条元语落点
