# Design: 闸 3 输出管控与闸 4 影子发布

## 目标与范围

把准入闸里最后两个空位补上，且**先定判据、后做实现**：

- 闸 3（输出管控）：原子执行**之后**、结果返回**之前**的确定性与值域判据
- 闸 4（影子发布）：`Tested → Shadow → Canary → Active` 的编排与证据门

不在本变更内：插件沙箱化、License/签名、信道容量上界。

---

## 闸 3：判什么、不判什么

前提是一个事实：原子**没有任何读写能力**（ABI v1 只有 `in` / `out` 两块缓冲区 + 一个 `run` 导出）。
因此它不能偷数据出去，但它仍然可以：

1. 把**编在代码里的常量**当成结果交出来（例如藏在某列的高位上）
2. 让输出**取决于行数或行序**，从而给自己开一条隐蔽信道
3. 写出**超出声明值域**的值，把调用方的下游弄脏

### 判据（四条判决 + 一条信号）

| # | 判据 | 类型 | 判什么 | 为什么是确定性的 |
| --- | --- | --- | --- | --- |
| O1 | 结构封闭 | 判决 | 输出只由**声明的列 + 声明的汇总位**构成；不允许多余列、缺列、列顺序变化 | 纯形状比对 |
| O2 | 值域 | 判决 | 每个值在声明类型与**既有**的 `minimum` / `maximum` 内（未声明时按 i32 边界兜底） | 逐值比较 |
| O3 | 大小上限 | 判决 | 输出总字节 ≤ 声明上限（既有行为，纳入同一份判决清单，统一出口） | 计数 |
| O4 | 批量-单条一致 | 判决 | 同一组输入，**批量一次算**与**逐条各算一次再拼**的结果必须逐值一致 | 两次确定性执行的比较 |
| O5 | 置换不变 | 判决（仅当契约声明 `commutative`） | 打乱输入行序后，输出行应随之重排、汇总位不变 | 同上，且只在声明后可判 |
| S1 | 常量位模式 | **信号** | 输出列中**与输入无关**的重复位模式（如整列同一个值、恒定的高位） | 逐值比较（不做统计） |

**不判**（写进协议文本，避免以后有人加）：

- 不做统计显著性检验、不做抽样、不做模糊测试——样本量撑不起结论，只会得到随机红绿
- 不判"输出是否合理"（业务正确性由契约的 `outputSchema` 与调用方负责）
- 不判性能（那属资源预算，已有 fuel/epoch）
- **不判 `commutative` 未声明的原子的置换不变性**：判不了就如实写"未判"，不假装判过

O4 / O5 的代价要说清楚：它们会对**同一次调用**多跑 2～3 次内核执行。
因此闸 3 的开关与档位进契约（`outputAudit: 'off' | 'standard' | 'strict'`），
默认 `standard`（O1/O2/O3/O4），`strict` 追加 O5 与 S1 的详细报告。

### 为什么 S1 是信号而不是判决

一个合法的原子完全可能"输出与输入无关"：比如"把整批行的税率取整到固定档位"、
"对空输入返回全 0 汇总"。这类原子不该被拦。
所以 S1 只写审计，交给人看；**判决必须是能说清"违反了哪条声明"的那几条**。

## 闸 4：影子发布的编排与证据门

准入状态机（已在实现里，与 `@speckit/wasm-modules` 的 `AdmissionStatus` 一致）：

```text
submitted → built → tested → shadow → canary → active
                       └──── 闸 4 管这一段 ────┘
rejected / revoked     任意状态可达（终态）
```

### 证据门

| 目标状态 | 必须已有的证据 | 缺证据时 |
| --- | --- | --- |
| `built` | 源码闸报告（闸 0）+ 构建产物哈希 | 拒绝 |
| `tested` | 静态闸报告（闸 1）+ 两次独立构建哈希一致（闸 2） | 拒绝 |
| `shadow` | 影子运行记录：**与谁并行**、观测了多久、差异条数 | 拒绝 |
| `canary` | 影子期的差异为 0（或差异已逐条审查并标注为预期） | 拒绝 |
| `active` | canary 期无未处理差异 | 拒绝 |

### 两条硬约束

1. **不得跳级**：`tested → active` 直接绑定被拒，错误里要说明缺哪一段。
2. **不得自证**：证据是平台记录的（闸报告来自闸实现、影子记录来自影子运行），
   调用方**不能**用请求体里的字段代替证据。

### `bindImplementation` 的变化

现在它接受任意状态。改后：`status: 'active'` 必须能沿状态机回溯到一条完整证据链；
`shadow` / `canary` 是**可绑定的**（这正是影子期的意义：绑定但不对外执行）。
对外执行仍受既有规则约束（`isRunnableStatus` 允许 shadow / canary / active 执行）——
这一点在 v1 保持不动，因为"影子期也要能被调用"是影子运行的前提。

## 与现有资产的关系

| 已有 | 本变更怎么用 |
| --- | --- |
| 闸 0 / 1 / 2（`wasm-modules/src/gates/*`） | 闸 4 直接消费它们的报告，不新造格式 |
| `atomic.moduleSha256` + `AdmissionTier` + `review` | 闸 4 的证据门字段来源；不新增表 |
| `AtomicExecutorService`（执行 + 审计） | 闸 3 挂在"执行完成 → 返回结果"之间，复用同一条审计出口 |
| `maxOutputBytes` / `outputSchema.columns` | O1 / O2 / O3 的声明来源 |
| `contract.cpuBudget`（fuel） | 闸 3 追加执行会消耗预算，需要在同一预算内结算，不额外放宽 |

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 闸 3 让既有原子从"能跑"变"被拦" | 上线前按契约逐个过一遍（tasks.md P4 有清单与命令）；判据是确定性的，结果可复现 |
| O4/O5 让执行成本成倍 | 档位进契约，默认 `standard`；`strict` 需显式声明；审计记录实际跑了几个内核回合 |
| 影子记录的字段设计过早 | v1 只要求四个字段（并行对象、起始时间、观测条数、差异条数），够用就好；等真的做影子运行器再扩 |
| 闸 4 拦住"紧急上生产" | 明确写出例外路径：吊销与回滚不需要闸 4（`revoked` 是终态，且随时可达） |

## 一处必须写在文档里的自我约束

闸 4 会让**已经在跑**的模块看不到影响（它们的实现已是 `active`），但会让**重新绑定**变严。
这不是意外：如果每次重新绑定都能凭一次请求跳过影子期，那闸 4 等于不存在。
迁移路径写在 tasks.md：为既有实现一次性补录证据，或在重新绑定时重走流程。
