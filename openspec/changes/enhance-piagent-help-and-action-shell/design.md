## Context

协议层（工具网关、确认令牌、知识版本）已在 PiAgent 文档与既有 P3 change 中落地或规划。
前端缺口是：用户如何在管理台里**唤起**助手，以及助手如何表达「我在讲解」vs「我要替你改数据」。

行业侧（deepseek 摘要，2026）：

- 管理台助手优先 **侧栏/当前页 dock**，悬浮球只适合作唤起；勿默认当成唯一交互。
- 上下文芯片（当前页 / 选中行）必须可见可移除。
- 工具调用要有 pending / success / error；破坏性动作必须显式确认。
- 用法答疑应 **grounded** 到已审核帮助/已发布知识，不知道就说不知道。
- 「全权接管」若不经确认，不适合本仓 ERP 写路径。

## Goals / Non-Goals

### Goals

- 同一面板承载帮助与代操；悬浮球与固定按钮打开同一面板。
- 写路径严格确认令牌；读路径可流式答疑。
- 与台面三分兼容：Portal / Console 都可挂壳入口，上下文随当前 org/app。

### Non-Goals

- 新造第二套 Agent 协议或旁路 `contracts/tools.json`。
- 业务页内嵌独立 Chat SDK。
- 无确认的批量静默写。

## Decisions

1. **入口**：固定壳按钮 = 主；悬浮球 = 可选附加；共用一个面板状态机。
2. **意图分流**：空态提供「问用法」「帮我操作」快捷；模型侧仍统一走编排，UI 用确认卡区分写意图。
3. **帮助 grounding**：优先已发布知识 / `pi_help_*`；禁止把未发布草稿当答疑源。
4. **代操**：只出 Interaction Plan / 确认卡；用户确认后前端调平台确认 API；编排器不签发令牌。
5. **与 enhance-ui-runtime 关系**：壳面板几何与「球非唯一」以该 change 为准；本 change 补产品意图与确认 UX。

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| 悬浮球遮挡分栏拖拽 / 主 CTA | 可拖位置 + 默认避开右下主操作区；可关 |
| 用户以为球=自动改数 | 写操作强制确认卡文案标明后果 |
| 与独立 piagent 页双会话混乱 | 默认同一会话后端；独立页标「历史/联调」 |

## Migration Plan

1. 壳固定按钮 + 面板 MVP（若 ui-runtime 任务未完成则本 change 一并交付最小面板）。
2. 加悬浮球触发器与空态双意图快捷。
3. 接通帮助检索与写确认卡。
4. Portal / Console 各挂一次；业务页扫描禁私挂。
